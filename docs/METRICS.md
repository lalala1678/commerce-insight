# 指标口径：真实数据核心版本

## A. 保留的地基教学样例

sample_data 下的合成数据仅供手算和回归测试，单位 BRL（巴西雷亚尔）；当前主页面已经使用真实 Olist 数据。

| 指标 | 口径 | 样例预期 |
|---|---|---|
| 已交付订单数 | status = delivered 的订单 ID 去重计数 | 3 笔 |
| 成交商品金额 | 上述订单的商品价格之和，不含运费 | 450.00 BRL |
| 平均客单价 | 同一订单集合的金额 / 订单数 | 150.00 BRL |

手算：demo-001 的两件商品 100 + 50；demo-002 为 200；demo-003 为 100。
因此金额 = 150 + 200 + 100 = 450，订单数 = 3。取消订单的 999 和处理中订单的 500 不参与。

SQL：sql/overview.sql。金额在数据库和 API 中使用整数分；前端除以 100 显示。
客单价作为展示性均值可以为小数分，空集合返回 null，不强行显示 0。

样例使用 demo_orders 与 demo_items 两张表。demo_items 每行代表一件商品，主键为 (order_id, item_id)。
接口 GET /api/overview 保留为旧教学接口；当前主页面使用 /api/dashboard，不调用它。

## B. 真实数据口径与实现边界

已实现成交金额、订单量、客单价、购买客户数、趋势、品类/地区/商品排名、低销量、交付时长、延迟率和评价。
复购、新老客及窗口 RFM 已实现，规则与样本分布见 [CUSTOMER_ANALYSIS.md](CUSTOMER_ANALYSIS.md)。环比仅描述实际结果，不推断经营原因。

### 基础集合与时间

- 主经营集合：Olist 中 order_status = delivered 的订单；使用抽取时最终状态，按 order_purchase_timestamp 归属。
- 日期范围 UI 为首尾日期包含；SQL 使用 `[开始日 00:00, 结束日次日 00:00)`，源时间不带时区，不擅自转换。
- 默认分析 2018-07，对比 2018-06；基础可选窗口 2017-01 至 2018-07。自然月天数不同须披露，2018-08 及更晚尾部不充当完整月。
- 周按星期一至星期日；筛选切断的周/月标注“不完整”。无覆盖的数据不显示为已证实的零销售。
- 品类筛选只累加命中商品项，订单数去重命中订单。地区使用客户州，不使用卖家州。没有任何品类筛选时保留未分类商品。
- 未知品类、缺翻译、缺支付/评价都不通过 inner join 丢弃已交付成交。缺支付不补为 0，不据此排除销售。

### 指标定义

| 指标 | 公式与统计集合 | 缺失 / 边界处理 |
|---|---|---|
| 成交商品金额 | 命中明细 price 求和；整数分或精确 Decimal | 不含 freight_value；不是含税净收入，不从支付表计算 |
| 订单量 | 命中已交付 order_id 去重计数 | 不能跨品类相加推得总订单数 |
| 客单价 | 成交商品金额 / 上述订单量 | 无订单返回 null |
| 购买客户数 | 命中订单对应 customer_unique_id 去重 | customer_id 只用于连接，不作客户身份 |
| 复购率 | 当前观察窗订单数 ≥2 的客户 / 观察窗购买客户 | 按同一筛选集合；无客户 null；不声称终身复购 |
| 新客数 | 当前窗口有购买，且全体可见已交付历史首次购买落入当前窗的客户 | 首次购买应在品类/地区筛选前计算；不是注册时间；披露左截断 |
| 老客数 | 当前窗购买客户中，历史首次已交付购买早于窗口的客户 | 新客 + 老客 = 当前购买客户 |
| R | 历史分析截止日期 − 截止日前最近购买日期 | 固定截止日，不用今天；同日为 0；仅属历史完成口径 |
| F | 指定回看窗口已交付订单去重数 | 不使用商品行数；先看分布，不强行五等分 |
| M | 与 F 相同回看窗口的成交商品金额 | 明确过滤维度；与金额口径一致 |
| 交付时长 | (送达时间 − 下单时间) 的总秒数 / 86400 | 使用有效非负时长样本；展示样本数、均值和中位数，不将缺失算 0 |
| 延迟率 | 送达自然日 > 预计送达日的已交付订单 / 两个日期均有效的已交付订单 | 预计日当天任何时间送达均不延迟；当前已交付有 8 笔缺送达日期 |
| 平均评分 | 每订单选定一条有效 1–5 分评价后求均值 | 披露评价样本与覆盖率；无评价不算 0 分 |
| 商品销量 | 符合范围的订单商品项行数 | 一项视为一件；没有库存，不代表去化率 |
| 环比 | (本期 − 比较期) / 比较期 | 比较期为 0 或覆盖不足时不可计算；百分比指标差用百分点 |

### 数据处理规则

- 原始评论原样留在受控数据区，不进入公开报告；订单级分析采用“最新回答时间”规则，回答时间并列时用 review_creation_date、review_id 排序作确定性选择，仍完全并列时按输入行序；记录折叠量。不得以 review_id 单列去重。
- RFM 使用公开规则 rfm-window-v1：R≤30天、F≥2次、M≥200BRL 的三项二分组合；覆盖所有窗口购买客户且互不重叠。阈值为探索规则，详见客户分析文档。
- 商品、支付、评价先各自处理到目标粒度，再连接。金额守恒应与原始商品项独立核对，不能只比较两个复用同一错误逻辑的接口。
- 承运早于下单或送达早于承运的记录增加质量标记，仅排除与该日期对有关的履约时长；不因承运异常整单删除。
- 预测特征只能用预测时可见信息；最终交付状态、最终评分、未来送达日期不能作为当时已知特征。

### 核心页面的补充说明

- 商品 TOP 按成交商品金额排序；低销量按件数升序、金额升序、商品 ID 排序，仅包括本期有已交付销售的商品。没有库存与上架信息，不能识别真正的零销量在售商品或库存滞销。
- 评价分布和准时/延迟组的评分都按订单统计，并展示订单数与有评价样本数；这是相关性观察，不表示配送导致评分变化。
- 订单明细的商品金额跟随品类筛选；整单商品金额、支付金额与履约仍属于整单。支付缺失显示缺记录，不能用 0 替代。
- 品类订单数存在交叉，不能相加得总订单量；商品金额按明细可加。所有关联先消除支付/评价的一对多再计算订单指标。
- 没有已交付记录、或观察日期与推荐窗口无交集时，推荐窗口为空，环比不可计算。接口仍返回可解释的空结果。
- 每次接口响应在同一个数据库读事务中取得数据版本和指标；不同次查询可能对应不同的导入版本，页面显示最近结果的版本。
