# 产品定位与用户验证计划

**状态：计划，尚未招募受访者、执行任务测试或接入商家试点。** 本文中的指标、目标和商业模式都是待验证假设，不是项目成果。

## 1. 当前产品到底是什么

这是基于 Olist 巴西多卖家平台匿名历史订单制作的**非商业作品集原型**。模拟使用者是需要核查销售结构、客户购买和履约评价变化的平台运营／商业分析人员。它以统一的历史已交付口径，将变化、贡献切片、样本量和待核查事项放在同一工作流中。求职展示的主要证据是指标可信、分析可追溯和交付可复现，而非已验证的市场需求。

- [在线版](https://lalala1678.github.io/commerce-insight/)只读取预先导出的聚合快照，筛选范围受菜单限制，没有订单级明细，也不连接实时业务系统。
- [本地版](../README.md)由 FastAPI 查询导入的历史数据，支持合法的日期／品类／客户州组合和订单明细；仍是分析原型，不具备商家账户、权限隔离、持续数据同步或运营执行功能。
- 数据不含真实退款、广告投入与流量、库存、采购及经营成本，不能计算退款率、广告 ROI、库存周转或利润。巴西多卖家平台样本不能直接说明中国单店商家的需求。
- Olist 数据按 [CC BY-NC-SA 4.0](DATA_SOURCE.md)用于非商业学习与展示。未来若提供收费服务，需改用获得相应授权的数据，并另行处理隐私、权限、部署及合同问题。

## 2. 要检验的价值假设

| 假设 | 观察办法 | 当前证据 |
|---|---|---|
| 运营人员能更快定位值得核查的销售变化 | 对照其现有表格／报表流程完成同一问题，记录到提出首个有依据的核查问题所用时间、路径和错误 | 未测试 |
| 统一口径降低误读 | 让使用者口头解释商品金额、订单量、比较周期和评价分母，记录错误及纠正过程 | 仅有代码和指标核对；未测试理解程度 |
| 报告能推动下一步行动 | 让使用者为一个变化写出待核查原因、所需补充数据、负责人和验证指标，观察是否能形成可执行任务 | 原型提供证据和建议；未观察真实采纳 |
| 值得持续使用或付费 | 在合法授权的数据试点中观察重复使用、手工时间变化与付费意愿 | 未验证，不作收入预测 |

首先检验前两项。若用户不能正确理解口径或完成核查任务，先改页面和报告，再考虑更多图表、预测或收费形式。

## 3. 一轮 3–5 人的任务测试

**招募**：寻找有电商运营、平台经营分析或相关报表经验的人；记录岗位、经验、平时使用的工具以及是否有多卖家平台经验。不要用只看过课堂案例的同学代替目标用户。不同背景分开记录，不把少量访谈解释为代表性市场结论。

**每人 25–35 分钟**：先说明这是巴西公开历史数据的作品集原型，不包含真实商家经营结果；征得记录同意。随后让受访者独立操作在线站点，用出声思考法，不提示按钮位置或预期答案。任务完成后才追问痛点和现有工作方式。只记录任务过程和必要的匿名反馈，不收集其企业数据或账号。

| 任务 | 可观察的完成条件 | 重点记录 |
|---|---|---|
| 销售变化 | 比较 2018 年 7 月与 6 月，区分总额和日均方向；找到至少一个品类或地区贡献，并提出还需核查的数据 | 完成时间、是否看见周期天数、是否无依据地归因促销 |
| 履约与评价 | 找到延迟组与按期组的评分及样本量；说明为何不能断言配送延迟导致低分 | 是否理解有效分母、缺评价和相关性边界 |
| 客户观察 | 选较长观察窗口，解释复购率分母以及 RFM 最近购买分组；指出未购买历史客户不在当前 RFM 内 | 是否误把数据内新客当注册新客、是否理解窗口长度 |
| 形成核查事项 | 从报告或图表中写一句事实、一个待验证假设、所需补充数据与验证指标 | 是否能区分事实、猜测和行动；遇到哪些信息断点 |

每项记录：成功／部分成功／失败、独立完成时间、走错的路径、原话、误读、所需提示及严重程度。建议另让受访者用其熟悉的表格／报表对同类问题估计或实测操作步骤，作为流程比较，不强行把不同企业的数据和 Olist 数字相比较。

**本轮判断规则（预先设定，执行后据实填写）**：若少于 4/5 人能独立说明销售总额与日均方向，或出现把相关性当因果、把静态范围当任意筛选的高风险误读，就先修正文案、路径或口径解释；不把完成时长直接宣称为“提效”。样本为 3 人时记录逐人表现，不套用 4/5 阈值。改版后用相同任务再次测量，并保存版本、日期、原始观察与修改原因。

## 4. 真实商家试点的前置条件

只有在获得合适的数据授权和运营方参与后，才考虑 2–4 周的只读小范围试点：选定一个组织与一个负责的分析任务，核对字段映射和指标定义，去标识化并控制访问，以现有工作流程为对照记录完成任务耗时、数据核对差异、重复使用及核查事项是否被采纳。真实数据不能沿用公开演示的静态导出与浏览器本地任务记录：需要按角色授权、隔离组织数据、抑制小样本分层，并审查报告导出。试点报告分别写事实、主观反馈、未验证原因和实施成本，不把使用后的指标变化自动归因于产品。

首轮测试不需要接入真实商家数据；在目前的 Olist 非商业许可与产品能力下，不计划收费，也不承诺 SaaS、多租户、实时预警或经营收益。是否继续产品化应依据用户任务证据、授权数据与运维成本重新决定。

## 5. 执行记录模板

每位受访者保存一行匿名记录：`参与者编号｜背景｜站点版本与数据版本｜任务｜结果｜独立完成时间｜关键误读｜原话｜所需提示｜建议修改`。集中归纳前先保留反例和失败路径；若后续没有找到目标用户，应标注“未验证”，不能用开发者自己的演示代替用户测试。
